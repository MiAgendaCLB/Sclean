Quiero que diseñes la estructura documental de un proyecto para utilizarla en Obsidian y Windows.

Debes seguir estrictamente las siguientes reglas.

# 1. Carpeta raíz

La carpeta raíz deberá numerarse automáticamente utilizando el siguiente consecutivo disponible.

Ejemplo:

1_Atlas
2_Vive
3_Fondecom
4_Tutela

El proyecto nuevo deberá ser:

5_NombreProyecto

Nunca asumir el número.
Siempre calcular el siguiente consecutivo.

---

# 2. Administración

Crear la carpeta:

00_Administracion

Contendrá únicamente:

Documento_Maestro.md
Cronologia.md
Inventario_Documentos.md

El Documento Maestro será el expediente analítico del proyecto.

No contendrá copias de documentos.

---

# 3. Etapas

Cada etapa será una carpeta numerada.

Ejemplo:

01_Demanda
02_Primera_Instancia
03_Segunda_Instancia

---

# 4. Subestructura de cada etapa

Cada etapa tendrá la siguiente estructura.

Ejemplo para la etapa 02:

02_Primera_Instancia

    2.1_Documento

    2.2_Correo

        Email.pdf

    2.3_Referencia_Pruebas.md

Las subcarpetas deberán conservar la numeración de la carpeta principal.

---

# 5. Documentos

Los documentos utilizarán consecutivo propio.

Ejemplo:

D01_20260623_Accion_de_Tutela.pdf

D02_20260706_Sentencia.pdf

Formato:

DXX_YYYYMMDD_Nombre.pdf

---

# 6. Pruebas

Existirá una única carpeta:

04_Pruebas

Nunca se clasificarán por tipo.

Todas las pruebas vivirán únicamente allí.

Formato:

P01_20260316_DICTAMEN_PCL_EPS_SOS.pdf

P02_20260408_HISTORIA_CLINICA.pdf

Nunca se duplicarán.

---

# 7. Referencia de pruebas

Cada etapa tendrá un archivo:

X.3_Referencia_Pruebas.md

Este archivo únicamente relacionará las pruebas utilizadas por dicha actuación.

Ejemplo:

Pruebas aportadas

P01
P02
P08

Nunca contendrá copias.

---

# 8. Correos

Cada actuación almacenará el PDF del correo dentro de:

X.2_Correo

No almacenar anexos.

Los anexos documentales vivirán únicamente dentro de:

04_Pruebas

---

# 9. Cronología

Cronologia.md será la bitácora oficial del proyecto.

Cada registro contendrá:

Fecha del hecho

Fecha del documento

Fecha de radicación

Fecha de recepción

Documento relacionado

Descripción

Observaciones

---

# 10. Inventario

Inventario_Documentos.md contendrá el consecutivo completo de:

Documentos (D)

Pruebas (P)

---

# 11. Documento Maestro

Será el expediente analítico del proyecto.

Toda interpretación, análisis y conocimiento generado se almacenará allí.

Nunca contendrá copias completas de documentos.

---

# 12. BAT

Generar un BAT inteligente que:

• detecte automáticamente el siguiente consecutivo de la carpeta raíz;

• cree únicamente elementos inexistentes;

• preserve toda la información existente;

• nunca sobrescriba archivos;

• nunca elimine contenido;

• utilice IF NOT EXIST antes de crear carpetas y archivos;

• sea idempotente (pueda ejecutarse múltiples veces sin alterar información existente).

• Al finalizar la ejecución deberá presentar un resumen indicando:

    - Carpetas creadas.
    - Carpetas que ya existían.
    - Archivos creados.
    - Archivos que ya existían.

• Finalmente deberá mostrar el árbol completo del proyecto generado utilizando el comando TREE.

• Si TREE no está disponible en el sistema, deberá indicarlo sin producir error.

• El resumen de ejecución forma parte obligatoria del estándar.

---

# 13. Entrega

Primero mostrar la estructura completa en árbol.

Después generar el BAT.

No agregar carpetas innecesarias.

La estructura debe estar adaptada específicamente al proyecto solicitado.
