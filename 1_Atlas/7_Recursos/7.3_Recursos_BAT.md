

## Objetivo

Documentar el uso de scripts BAT dentro del ecosistema Atlas.

---

# Principios

Todos los scripts BAT deberán cumplir obligatoriamente los siguientes principios.

- Crear únicamente elementos inexistentes.
- Preservar toda la información existente.
- Nunca sobrescribir archivos.
- Nunca eliminar contenido.
- Ser completamente idempotentes.
- Poder ejecutarse múltiples veces sin modificar información previamente creada.

---

# Funciones Permitidas

Los BAT podrán:

- Crear estructuras de carpetas.
- Crear archivos base.
- Generar inventarios.
- Verificar estructuras.
- Automatizar tareas repetitivas.
- Crear proyectos siguiendo estándares documentales.
- Inicializar proyectos nuevos.

---

# Restricciones

Los BAT nunca podrán:

- Sobrescribir documentación existente.
- Modificar documentación oficial sin autorización explícita.
- Renombrar documentos automáticamente.
- Eliminar carpetas.
- Eliminar archivos.
- Reorganizar información existente.
- Mover documentación sin autorización.

---

# Reglas Técnicas

Todo BAT deberá utilizar verificaciones previas antes de crear cualquier elemento.

Ejemplos:

if not exist "Carpeta" mkdir "Carpeta"

if not exist "Documento.md" (
    type nul > "Documento.md"
)

No se utilizarán instrucciones que sobrescriban archivos existentes.

No se utilizarán instrucciones de eliminación (DEL, ERASE, RMDIR, RD) salvo autorización expresa.

---

# Idempotencia

Todo BAT deberá poder ejecutarse repetidamente obteniendo siempre el mismo resultado.

Si una carpeta existe:

→ no deberá modificarse.

Si un archivo existe:

→ no deberá recrearse.

Si un proyecto existe parcialmente:

→ únicamente deberán crearse los elementos faltantes.

---

# Buenas prácticas

Siempre utilizar:

IF NOT EXIST

antes de crear:

- carpetas;
- archivos;
- estructuras.

Todo BAT deberá diseñarse bajo el principio de "No Destrucción de Información".

La preservación de la información existente tiene prioridad sobre cualquier automatización.
# Reporte de ejecución

Todo BAT deberá generar un reporte al finalizar.

El reporte deberá indicar como mínimo:

## Carpetas

- Creadas.
- Ya existentes.

## Archivos

- Creados.
- Ya existentes.

Nunca deberá reportar elementos inexistentes como creados.

---

# Visualización

Al finalizar, el BAT deberá mostrar la estructura completa del proyecto utilizando:

TREE

Si TREE no estuviera disponible en el sistema operativo, deberá informar dicha situación sin interrumpir la ejecución.

---

# Auditoría

El reporte de ejecución constituye una auditoría mínima del proceso realizado.

Debe permitir identificar fácilmente:

- qué fue creado;
- qué ya existía;
- que no se modificó información existente.
