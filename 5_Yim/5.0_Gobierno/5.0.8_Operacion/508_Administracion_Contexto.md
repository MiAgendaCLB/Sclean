# Administración del Contexto

## Propósito

Definir cómo se identifica, selecciona, entrega, actualiza y descarta el contexto utilizado durante la ejecución de Yim.

El objetivo es garantizar que cada rol disponga únicamente de la información necesaria para realizar su trabajo, preservando la coherencia metodológica y reduciendo el consumo innecesario de contexto.

---

# Definición de contexto

Se considera contexto toda la información utilizada para ejecutar una actividad dentro de Yim.

El contexto puede incluir:

- objetivo del proyecto;
- documentación oficial;
- decisiones aprobadas;
- estado del proyecto;
- resultados previamente validados;
- Hallazgos registrados;
- restricciones conocidas.

No toda la información disponible constituye contexto para una tarea.

---

# Principios

La administración del contexto deberá cumplir los siguientes principios:

- suficiencia;
- relevancia;
- trazabilidad;
- actualidad;
- mínima transferencia;
- ausencia de duplicidad.

---

# Responsabilidad

La administración del contexto es responsabilidad del Orquestador.

Los demás roles únicamente consumen el contexto recibido y producen una salida correspondiente a su disciplina.

---

# Selección del contexto

Antes de asignar una tarea, el Orquestador deberá identificar:

- el objetivo inmediato;
- la información imprescindible para alcanzarlo;
- la documentación oficial relacionada;
- las decisiones vigentes;
- los Hallazgos relevantes.

Toda información no necesaria deberá excluirse.

---

# Contexto mínimo

Cada tarea deberá ejecutarse utilizando el menor contexto posible sin comprometer la calidad del resultado.

El contexto mínimo deberá permitir al rol:

- comprender el objetivo;
- conocer las restricciones;
- identificar la documentación oficial aplicable;
- producir una salida verificable.

---

# Actualización del contexto

Después de validar una salida, el Orquestador actualizará el contexto operativo incorporando únicamente:

- decisiones aprobadas;
- documentación oficial actualizada;
- estado del proyecto;
- Hallazgos registrados.

No se incorporarán borradores, hipótesis ni información pendiente de validación.

---

# Persistencia

El conocimiento permanente deberá almacenarse exclusivamente en la documentación oficial.

Las conversaciones y el contexto temporal nunca constituyen una fuente oficial de conocimiento.

---

# Consistencia

Toda información utilizada deberá ser consistente con:

- la Metodología Atlas;
- la documentación oficial;
- las decisiones metodológicas vigentes.

Ante cualquier contradicción prevalecerá la documentación oficial.

---

# Reducción del contexto

Siempre que sea posible, el Orquestador deberá reducir el contexto entregado mediante:

- referencias a documentos oficiales;
- eliminación de información repetida;
- exclusión de decisiones obsoletas;
- exclusión de resultados ya consolidados.

---

# Contexto inválido

Se considerará contexto inválido cualquier información que:

- contradiga la documentación oficial;
- no tenga trazabilidad;
- corresponda a versiones reemplazadas;
- no haya sido validada;
- pertenezca a otra disciplina sin haber sido consolidada.

El contexto inválido no podrá utilizarse para producir documentación oficial.

---

# Criterios de aceptación

La administración del contexto será correcta cuando:

- cada rol reciba únicamente la información necesaria;
- toda referencia sea trazable;
- no exista información duplicada;
- la documentación oficial permanezca como única fuente de verdad;
- el contexto temporal pueda descartarse sin pérdida de conocimiento;
- el proyecto pueda continuar utilizando exclusivamente la documentación oficial.
